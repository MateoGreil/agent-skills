# Markdown tables for Slack

Use the three Python programs bundled beside this document. In the commands below, replace `<skill_dir>` with the absolute directory containing this `SKILL.md`; installation locations and the current working directory are not interchangeable.

## Establish the input and delivery permission

Eligible table material is limited to:

- Markdown supplied by the user in the conversation.
- A table already generated by the assistant in this conversation.
- Content from a file the user explicitly identified as the input.

If none is available, request a table or an explicit input path and wait. Clipboard contents are not an input source. Do not look through unrelated files to obtain table data.

Select delivery according to the request:

- For a manual paste, or when no recipient has been confirmed, prepare the clipboard output without sending a message.
- For a request to publish directly, invoke the API sender only with a user-confirmed channel or DM ID. Clarify an ambiguous destination before posting.

An approved Markdown file can be passed directly to the scripts. Otherwise save the eligible table text to `/tmp/table.md`. Each converter uses the first table it recognizes in that file.

## Runtime prerequisites

- Run the scripts with Python **3.10 or newer**.
- Clipboard delivery needs Linux, PyGObject, GTK4 and a working X11 or Wayland desktop session. Ubuntu packages are `python3-gi` and `gir1.2-gtk-4.0`.
- API delivery needs browser-session authentication configured locally through `slackcli`. The sender reads the default workspace from `~/.config/slackcli/workspaces.json`. Keep that configuration local; do not print, copy into messages or include its tokens in task artifacts.

## Prepare a Linux paste

Generate the two files, then start their clipboard provider:

```bash
python3 "<skill_dir>/md2slack.py" /tmp/table.md --html-out /tmp/table.html --tsv-out /tmp/table.tsv
setsid nohup python3 "<skill_dir>/clip_table.py" /tmp/table.html /tmp/table.tsv > /tmp/clip_table.log 2>&1 &
```

`clip_table.py` serves the HTML file as `text/html` and the tab-separated file as both `text/plain` and `text/plain;charset=utf-8`. Both representations must be offered together. The helper must remain running while the user pastes; detaching it with `setsid` avoids tying its lifetime to the launching shell.

Check the advertised formats without reading clipboard content. Where `xclip` is available:

```bash
xclip -selection clipboard -t TARGETS -o
```

Confirm that the provider is still alive and that the format list includes `text/html` and `text/plain` before reporting that the paste is prepared. Then ask the user to paste in Slack with Ctrl+V and accept table formatting if offered. A subsequent copy replaces this provider's clipboard ownership; start the helper again if another paste is needed.

## Publish to a confirmed recipient

Substitute the approved destination ID:

```bash
python3 "<skill_dir>/send_slack_table.py" /tmp/table.md CHANNEL_OR_DM_ID
```

A third positional argument sets the message introduction; omitting it uses `Markdown table`. The script builds a Slack `table` block with `rich_text` cells, applies bold to the header, and handles inline links, backtick code and double-asterisk bold. It calls `chat.postMessage` using the locally configured workspace.

The first request puts the table in `blocks`. If Slack returns a response without `ok: true`, the script makes one attachment-based attempt. Read the final JSON result: only `ok: true` indicates reported delivery, while `error` describes rejection and `ts` identifies a successful message. A printed response or a zero exit status alone is not evidence of success.

## Handle unavailable prerequisites or invalid input

- A missing `gi` import or GTK typelib requires the Linux clipboard dependencies; a missing display requires a desktop session. Report the clipboard failure rather than claiming a prepared paste. API delivery still requires the confirmed recipient and posting request above.
- For authentication failures, have the user configure local browser-session access with `slackcli auth login-browser`; never request tokens in the conversation.
- The parser expects a pipe-separated header followed by a separator row. If it reports no table, ask the user to correct the supplied input. It is a small table parser, not a complete Markdown implementation.
- Report file, transport and response-decoding errors instead of claiming a posted message.
